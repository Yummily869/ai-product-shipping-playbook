# Skill · 产品侧效果评测标准

> 用在什么时候：需要回答「产品对这个AI产品的预期以及关注重点」——包括提测评估、决定要不要放量。

---

## 我遇到的难题

AIGC 产品有个绕不开的矛盾：

> **用户最终感受到的是「这条视频好不好看」，但「好不好看」既没法量化，也没法定位到具体环节。**

我一开始试过两种做法，都不太行：

| 做法 | 问题 |
|---|---|
| 只打总分（这条片子 7 分） | 知道好不好，但不知道该改哪个节点 |
| 只看节点技术指标（识别准确率 92%） | 每个节点都达标，合起来还是不好看 |

后来我们的做法是：**按链路环节拆权重，每个环节再拆成能判定的子项。**

---

## 我们用的三维框架（智能剪辑）

```
                    评测指标
                       │
      ┌────────────────┼────────────────┐
      │                │                │
  高光识别质量      文案生成匹配度     智能包装观感
     30%              40%               30%
      │                │                │
  ├─内容准确性     ├─内容相关性     ├─字幕排版合理性
  └─画面质量       ├─风格适配性     ├─视觉风格统一性
                   └─叙事连贯性     └─文字模板适配性
```

三个维度对应链路的三个阶段：

| 维度 | 对应阶段 | 回答什么 |
|---|---|---|
| 高光识别质量 | 输入理解 | 选对片段了吗 |
| 文案生成匹配度 | 内容生成 | 讲对故事了吗 |
| 智能包装观感 | 视觉呈现 | 呈现得好看吗 |

**这个拆法最大的好处是：总分低的时候能直接定位到是哪个阶段的问题。**

### 关于权重我的思考

文案给 40% 是因为：
- **感知最直接**——字幕是视频里唯一的显性文字，一句尬文案会毁掉整条片
- **失败模式最多**——不相关、风格不搭、前后不连贯，三种失败方式
- **最能体现差异化**——这是模板方案做不到的部分

高光识别虽然是**错误代价最高**的环节（选错了后面全错），但我们没给它更高权重。我的理由是：**它的问题会通过文案和观感体现出来**，如果再给它高权重，同一个问题会被计分两次。

⚠️ 这个权重分配是我们讨论出来的，不敢说是最优的。我也没有对照组能验证换个权重会不会更准。

## 各子项的判定标准

**这一层是整个评测框架里最关键的。** 我一开始只写了子项名字，两个人打分差得很远，分数完全不可信。

### 高光识别质量

| 子项 | 判定标准 |
|---|---|
| 内容准确性 | 选出的片段是否包含明确的人物动作/事件，而非静态空镜或废片 |
| 画面质量 | 是否清晰、无明显抖动、无虚焦、主体未被裁切 |

内容准确性的评分细则：

```
2 分（好）：有明确的人物动作或事件，构图完整
1 分（可用）：有内容但表现力弱（比如平缓的风景移镜）
0 分（差）：静态空镜、纯过渡帧、废片（黑屏/糊/手指遮挡）
```

**我发现一个挺有用的经验**：把 0 分定义清楚比把 2 分定义清楚更重要。

因为大家对「什么算好」的理解差异很大，但对「这是废片」的判断高度一致。**从坏的一端锚定标准，两个人的一致性明显更高。**

### 文案生成匹配度

| 子项 | 判定标准 | 常见失败 |
|---|---|---|
| 内容相关性 | 文案说的是不是画面里真实存在的东西 | 画面是猫，文案写「和朋友的午后」 |
| 风格适配性 | 是否符合用户选的风格 | 用户选「诗意」，输出吐槽风 |
| 叙事连贯性 | 多条字幕连起来是不是一个完整表达 | 每句单看都行，连起来是六句无关的话 |

**「叙事连贯性」是我们后来才加的子项**，加之前完全没测。

判定方法很简单：**把所有字幕抽出来连读**。像一段话就通过，像六条独立的朋友圈就不通过。

我觉得这个子项特别重要，因为**它是「大模型编排」相对于「模板填充」的核心优势**。模板方案也能做到「每句话单看都对」——如果连贯性不达标，我们这个功能就失去了存在的理由。

**风格适配性有个坑**：我们发现有些 badcase 的根因不在文案节点，而在上游内容标签带了风格语义，和用户选的风格冲突。详见 [Prompt 撰写 · Context 坑一](../prompt-writing/README.md)。

> 这让我意识到：**评测分数低的环节，根因可能在上游。**

### 智能包装观感

| 子项 | 判定标准 | 常见失败 |
|---|---|---|
| 字幕排版合理性 | 是否遮挡主体、出屏、换行在语义断点 | 字幕压在人脸上；长句被裁断 |
| 视觉风格统一性 | 全片字体/配色/转场是否一套风格 | 前三段清新风，后两段变科技风 |
| 文字模板适配性 | 模板是否匹配内容调性 | 温情内容配了夸张综艺花字 |

**这三项我后来发现有两项其实能用规则解决**：

| 子项 | 能规则化吗 |
|---|---|
| 字幕排版 | ✅ 大部分可以（人脸检测避让、安全区约束、按标点换行） |
| 风格统一性 | ✅ 完全可以（全片共用一套配置，不逐段选） |
| 模板适配性 | ❌ 需要模型判断内容调性 |

**这个发现改变了我的一个习惯**：评测发现问题后，我第一反应不再是「改 Prompt」，而是先问「这个能不能用规则解决」。规则的稳定性比依赖模型高得多。

## 执行方法

### 一 · 双人交叉，先算一致率再看分数

这是我踩过的坑。第一次评测我们两个人分别打分，直接算了平均分，报了个 6.8 分。

后来发现两个人的打分差异很大，那个 6.8 分基本是没意义的——**分数波动来自我们两个人的标准不同，不是来自产品变化。**

现在我会先算一致率：

```
一致率 = 两人打分完全相同的样本数 / 总样本数
```

| 一致率 | 意味着 | 该做什么 |
|---|---|---|
| > 80% | 标准清晰 | 分数可信，继续 |
| 60-80% | 标准有歧义 | 找出分歧样本，细化判定标准 |
| < 60% | 标准失效 | **停下来重写细则，别看分数** |

### 二 · 基准测试集：只增不改

| 规则 | 为什么 |
|---|---|
| 分布和线上一致 | 否则选出的是「在测试集上好」的方案 |
| **只增不删** | 删掉的样本往往是「我们解决不了的」，删了就永远发现不了 |
| 每个线上 badcase 都补进去 | 这是测试集唯一正确的增长方式 |
| 规模不必大 | 我们用 30-50 个，够看趋势 |

必须包含的极端样本（这些我们都是踩坑之后才补的）：
- 纯黑/纯白画面
- 无人声素材
- 超短（<3 秒）/ 超长（>5 分钟）
- 单素材 / 超多素材（20+）
- 各种画幅（横屏/竖屏/方形）

**「只增不删」这条我觉得最重要。** 有一次我想把一个一直过不了的样本删掉，被提醒了一下才意识到：那个样本恰好代表了一类我们处理不好的输入，删了之后线上一定还会出问题，而且再也不会被测出来。

### 三 · 用大模型打分：能用，但要先对齐

用模型评分能省很多人力，但我踩过一个坑：直接就用了，没验证它和人的判断是否一致，结果分数完全不对。

正确的流程：

```
① 人工评 50 个样本 → 作为标准答案
② 让模型评同一批 → 算模型和人的一致率
③ 一致率 > 80% → 可以用模型做大批量评测
④ 一致率 < 80% → 改评分 Prompt，回到 ②
⑤ 上线后定期抽样人工复核，防止漂移
```

哪些子项适合用模型评：

| 子项 | 适合吗 | 为什么 |
|---|---|---|
| 内容相关性 | ✅ | 有客观依据（画面 vs 文案） |
| 叙事连贯性 | ✅ | 纯文本判断 |
| 风格适配性 | ⚠️ 谨慎 | 风格是主观概念，需要充分 Few-shot |
| 画面质量 | ❌ | 用传统 CV 指标（清晰度/抖动）更准更便宜 |
| 字幕排版 | ❌ | 用规则检测（人脸框重叠/出屏）就行 |

**最后两行是我后来才想到的**：不是所有子项都该用大模型评。能用确定性方法测的，用确定性方法更准更快更便宜。

### 四 · 要输出「问题分布」，不只是分数

我第一版评测报告只有一个总分，被问「所以我们该先改什么」，答不上来。

后来改成输出失败模式分布：

```
本轮评测 50 个样本，综合 6.8 / 10

失败模式分布：
  文案与画面不相关       32%  ← 主要矛盾
  字幕遮挡主体           24%
  叙事不连贯             18%
  选中了废片             14%
  风格不符合用户选择     12%
```

**这张分布表直接就是迭代优先级。** 而 6.8 分这个数字告诉不了我该先做什么。

## 完整流程

```
① 定维度和权重
      ↓
② 写清每个子项的判定标准（尤其把 0 分定义清楚）
      ↓
③ 建基准测试集（分布对齐 + 只增不改）
      ↓
④ 双人交叉打分 → 先看一致率，再看分数
      ↓
⑤ 输出失败模式分布 → 得到迭代优先级
      ↓
⑥ 针对 Top1 失败模式，一次只改一处
      ↓
⑦ 在同一测试集上复测 → 对比
      ↓
⑧ 线上 badcase 补进测试集 → 回到 ③
```

第 ⑥ 步的「一次只改一处」是我在 Prompt 调优时学到的，评测这里同样适用。

## 自检清单

- [ ] 拆了维度，不是只打总分
- [ ] 权重有理由，且避免了上游问题重复计分
- [ ] 每个子项都定义了 0 分是什么
- [ ] 先算一致率再看分数（< 60% 就停下）
- [ ] 测试集分布和线上对齐
- [ ] 测试集只增不删
- [ ] 极端样本都覆盖了
- [ ] 能用规则/CV 测的子项没用大模型
- [ ] 用大模型评分前验证过和人的一致率
- [ ] 输出了失败模式分布，不只是分数
- [ ] 发现问题时先判断能否用规则解决、根因是否在上游

## 我还没搞清楚的

- 权重（30/40/30）是我们讨论出来的，没有对照组验证。换成 20/50/30 会不会更准？不知道。
- 一致率的 80% 阈值是我拍的，不知道行业标准是多少。
- 测试集 30-50 个够不够？我感觉够看趋势，但没有统计依据。
- 用大模型评分的成本我没算过，如果每轮评测都跑一遍，可能也不便宜。

## 关于 Agent 类产品的评测

我做的是 AIGC 类产品，评测的是「产出物好不好」。

后来了解到 Agent 类产品的评测逻辑完全不同——因为 Agent 在给出答案之前会规划、调工具、检查返回、重试，**最终回复只是一条长路径的最后一步**。这意味着 Agent 可能每个工具都调对了但没完成任务，也可能答对了但路径极其低效。

我把查到的公开资料整理在了 [Agent 评测参考](./agent-evaluation-notes.md)，但需要说明：**这部分我没有实践过，只是文献整理。**
