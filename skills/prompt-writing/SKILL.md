# Prompt 撰写

把一句话需求转换为可直接使用的完整 Prompt。

---

## Input

用户可以只给一句话，也可以给完整背景。缺失的信息由本 skill 按 Step 1 的规则补齐或使用默认值，**不向用户反复追问**。

典型输入：

```
给我生成一段用于视频复刻的 prompt，视频结构需与参考视频一样，人物替换成我自己
写一个从用户评论里提取标签的节点 prompt，要输出 JSON
帮我改一下这个 prompt，它总是多输出一堆解释文字
```

---

## Application

### Step 1 · 判定 Prompt 类型

不同类型的 Prompt 结构完全不同，先归类再套模板。

| 类型 | 特征 | 用哪个模板 |
|---|---|---|
| **A. 生成类** | 输出是图像/视频/音频，消费者是人 | [模板 A](#模板-a生成类视频图像) |
| **B. 结构化输出类** | 输出是 JSON/字段，消费者是下游程序 | [模板 B](#模板-b结构化输出类) |
| **C. 对话类** | 多轮交互，输出是自然语言 | [模板 C](#模板-c对话类) |

判定依据：**问「谁消费这个输出」**。人看 → A 或 C；程序解析 → B。

### Step 2 · 补齐关键槽位

按类型检查必填项。缺失时用推断值填充，并在输出末尾标注哪些是推断的。

**A 类（生成）必填**
| 槽位 | 缺失时怎么办 |
|---|---|
| 保持不变的部分 | 从需求中提取"需与…一样"的表述 |
| 需要替换的部分 | 从需求中提取"换成…"的表述 |
| 画幅与时长 | 默认竖屏 9:16、5-10 秒（短视频场景基准） |
| 风格调性 | 默认"与参考视频保持一致" |

**B 类（结构化）必填**
| 槽位 | 缺失时怎么办 |
|---|---|
| 输出字段与类型 | 从需求推断最小字段集，标注为推断 |
| 无结果时的返回 | 一律补上空值定义（**必填，不可省略**） |
| 字段取值范围 | 枚举类字段必须给完整枚举 |

**C 类（对话）必填**
| 槽位 | 缺失时怎么办 |
|---|---|
| 不能说什么 | 按场景补通用底线（不承诺、不编造） |
| 不知道时说什么 | 一律补上兜底话术（**必填**） |
| 回复长度 | 默认 100 字以内 |

### Step 3 · 按模板生成

见下方三个模板。

### Step 4 · 过自检清单

生成后逐条检查 [自检清单](#自检清单)，不通过的直接改，不要输出带缺陷的 Prompt。

### Step 5 · 输出

输出格式固定为：

```
【生成的 Prompt】
（可直接复制使用的完整内容，放在代码块里）

【关键设计说明】
- 2-4 条，只说非显而易见的设计决策及其原因

【推断的信息】
- 列出用户未提供、由本 skill 补齐的槽位（无则省略此节）

【调优建议】
- 效果不达预期时，优先调整哪一部分
```

## 五要素构造规则

三个模板共用的底层规则。

### Role · 角色

| 规则 | 说明 |
|---|---|
| 用职业身份，不用能力描述 | ✅「你是一名短视频平台的资深内容运营」<br>❌「你擅长写吸引人的文案」 |
| 加平台/场景限定词 | 「电商客服」→「快手电商售后客服」，限定词带出平台特有表达习惯 |
| 多节点链路各节点用不同 Role | 「导演」自带叙事节奏判断，「运营」自带传播效果判断 |

职业身份自带一整套隐含标准，能力描述只是形容词。

### Task · 任务

| 规则 | 说明 |
|---|---|
| 写产出物，不写动作 | ✅「选出 5 个片段并说明入选理由」<br>❌「分析这些素材」 |
| 一个 Prompt 一个产出物 | 多产出物拆成多个节点，否则靠后的任务会被敷衍，且无法定位失败点 |
| 主观判断必须给依据和优先级 | 「最精彩」不可执行，要展开为带优先级的判定列表 |

### Context · 上下文

| 规则 | 说明 |
|---|---|
| **语义空间不重叠** | 多来源信息拼进同一个 Prompt 时，各自描述的维度不能交叉。<br>例：内容标签只描述"拍了什么"，严禁出现"搞笑/治愈/吐槽"这类带风格语义的词——否则与用户选的风格标签冲突，模型随机二选一 |
| **每个字段写失效条件** | 每个塞进 Context 的字段都要回答"什么条件下不该用它"。<br>例：上游推荐结果 → 用户已有显式输入时不该用；历史对话 → 超过 N 轮或话题切换时不该用 |
| 做减法测试 | 每个字段问"去掉它效果会变差吗"。没测过的字段通常可以去掉。字段越多，成本越高、注意力越稀释、冲突概率越大 |

### Rules · 规则

| 规则 | 说明 |
|---|---|
| **反面清单优于正面要求** | 具体的禁止项遵循度高于抽象的正面要求。<br>❌「文案要具体生动」<br>✅「禁止输出：美好/精彩/难忘/治愈（无信息量形容词）、这就是生活/记录美好时光（空泛总结句）、绝了/爱了/yyds（平台黑话）」 |
| **模糊词翻译成结构约束** | 「粒度细」「具体」「生动」都不可执行，要翻译成可判定的结构。<br>例：「标签要具体」→「每个标签必须由『人群属性 + 场景 + 需求』三维度组合，缺任一维度视为无效」 |
| Few-shot 成对给，且说明原因 | 只给正确示例，模型学到的是表面模式；给出「✅ 正确（因为…）/ ❌ 错误（因为…）」才是判断标准 |

### Format · 输出格式

| 规则 | 说明 |
|---|---|
| 结构定义 + 一个完整示例 | 只给字段说明不给示例，格式错误率明显更高 |
| 字段约束就近写 | 「reason 不超过 20 字」写在字段示例旁，遵循度高于写在 Rules 里 |
| **必须定义「无结果」怎么表达** | 不定义的话模型会用自然语言解释为什么没结果，下游解析直接失败 |
| 嵌套不超过 3 层 | 超过 3 层格式错误率上升，宁可拆成两个节点 |
| 结构化输出必写三条禁令 | ①不加前置说明后置总结 ②不用代码块包裹 ③不输出思考过程 |

## 模板 A：生成类（视频/图像）

生成类 Prompt 的核心是**把"保持什么"和"改变什么"分开写清楚**。模型生成效果差通常是这两者边界模糊——该保持的变了，该变的没变。

```
# 核心任务
基于参考视频生成一条新视频。

# 必须严格保持的（与参考视频完全一致）
- 镜头结构：分镜数量、每个镜头的时长比例、镜头切换时机
- 运镜方式：推拉摇移的类型、速度、幅度
- 节奏：转场节点与音乐/动作的对齐关系
- 构图：主体在画面中的位置、景别（远景/中景/特写）序列
- 光影氛围：色调、明暗对比、光源方向

# 必须替换的
- 主体人物：替换为提供的人物素材
  - 保持人物在画面中的位置、朝向、动作幅度与参考视频一致
  - 保持人物与背景的空间关系不变
- （如有）场景/商品：______

# 严格禁止
- 禁止改变分镜数量与顺序
- 禁止添加参考视频中不存在的转场、特效、贴纸
- 禁止改变画幅比例（输出保持 9:16 竖屏）
- 禁止在画面中生成任何文字、字幕、水印
- 禁止改变整体色调与光影风格

# 输出规格
- 画幅：9:16
- 时长：与参考视频一致
- 帧率：与参考视频一致
```

### A 类的三条关键设计

**① 保持项要拆到「可判定」的粒度**

「保持风格一致」是无效指令。必须拆成镜头结构 / 运镜 / 节奏 / 构图 / 光影五项——每一项模型都能独立对齐。

**② 替换项要写「什么跟着变、什么不变」**

只说「人物替换成我」不够，模型可能连带改变人物位置和动作。必须显式声明：**替换外观，但保持位置、朝向、动作幅度、与背景的空间关系不变。**

**③ 针对命令禁止的内容写入「严格禁止」**

目前生成模型经常在画面里自作主张加字幕。如果下游还要叠自己的字幕，会出现双字幕。这条在竖屏素材上尤其高发。

### A 类的常见问题与对策

| 问题 | 对策 |
|---|---|
| 生成结果与参考视频结构不一致 | 检查保持项是否拆到了五个维度，笼统写"结构一致"无效 |
| 人物替换后位置/动作变了 | 在替换项下补充「保持位置、朝向、动作幅度不变」 |
| 画面出现多余文字或字幕 | 禁止项补「禁止生成任何文字」；若原视频自带字幕，需在生成前用字幕擦除处理，seedance2.0目前仅靠 Prompt 无法可靠消除；Minimax H3字幕处理效果较好 |
| 横屏正常、竖屏效果差 | 属于模型能力在该画幅上的分布问题，Prompt 无法解决，需换模型或补前置处理 |
| 输出画幅错误 | 输出规格中显式写死画幅，不要依赖模型从参考视频推断 |

## 模板 B：结构化输出类

```
# Role
你是一个 ______（职业身份 + 平台/场景限定词）。

# Task
______（写产出物，不写动作）

# Context
【______】
{变量名}
（使用条件：______ 时不参考此字段）

# Rules
底线：
1. ______ 必须严格来自 ______，禁止捏造或推测
2. 若 ______ 中没有相关信息，返回 ______，禁止自行给结论

内容约束：
3. ______（用结构约束表达，如"必须由 X+Y+Z 三维度组合"）
4. 禁止输出以下内容：______（具体清单，不是抽象要求）

格式禁令：
5. 直接输出 JSON，不要添加任何前置说明或后置总结
6. 不要用代码块包裹
7. 不要输出思考过程

# Few-shot
✅ 正确：______
   为什么正确：______
❌ 错误：______
   为什么错误：______

# Format
{
  "字段名": "值的说明，含长度/取值范围约束"
}

无结果时返回：{"字段名": []}，不要返回任何解释性文字。
```

### B 类的常见问题与对策

| 问题 | 对策 |
|---|---|
| 输出前后带解释文字 | Prompt 加格式禁令三条；**同时**在解析侧用正则抽取首个 JSON 对象 |
| 输出混入思考过程 | 优先检查模型参数中的思考模式是否显式关闭（不是"不覆盖走默认值"）；Prompt 侧加禁令；解析侧剥离 `<think>` 块 |
| 输出粒度过粗（如只返回"女性""年轻"） | 把模糊要求翻译成维度强制组合，并给成对示例 |
| 枚举字段返回了范围外的值 | Format 中列出完整枚举，并加「只能从以上取值中选择」 |
| 无结果时返回自然语言 | Format 末尾补空结果定义（这是最常被遗漏的一条） |
| 偶发格式错乱 | Prompt 侧降低发生率，解析侧降低影响面，**两侧都要做** |

## 模板 C：对话类

```
# Role
你是一个 ______（职业身份 + 平台/场景限定词）。

# Task
______（明确产出物：一段可直接发送给用户的回复）

# Context
【______】
{变量}

【历史对话】
{chat_history}
（若超过 5 轮或话题已切换，仅参考最近 2 轮）

# Rules
底线：
1. ______ 必须严格来自 ______，禁止捏造
2. 若无相关信息，回复"______"，禁止自行给结论
3. 不承诺任何 ______ 未明确提及的内容

形式：
4. 回复不超过 ______ 字
5. 结构固定：______ → ______ → ______
6. 不用 emoji，感叹号不超过 1 个

禁止：
7. 禁止使用无实质内容的话术：______（具体清单）

# Format
{
  "reply": "发送给用户的回复文本",
  "need_transfer": false,
  "source": "引用依据的ID，无引用时为空字符串"
}
```

### C 类的两条关键设计

**① 必须给模型「表达无法处理」的出口**

`need_transfer` 这类字段的作用是让模型能说"我处理不了"。没有这个出口，模型会硬答，并且会编造。

**② 必须写清"不知道时说什么"**

只写「禁止捏造」不够，要给出具体的兜底话术。禁止但不给替代方案，模型仍会自行发挥。

## 完整示例

**输入**

> 给我生成一段用于视频复刻的 prompt，视频结构需与参考视频一样，人物替换成我自己

**输出**

【生成的 Prompt】

```
# 任务
基于提供的参考视频，生成一条新视频。新视频需完整复刻参考视频的视听结构，
仅将画面中的主体人物替换为用户提供的人物素材。

# 必须严格保持（与参考视频完全一致）
1. 镜头结构：分镜数量、顺序、每个镜头的时长比例
2. 运镜方式：每个镜头的推/拉/摇/移类型、速度、幅度
3. 剪辑节奏：转场时机、转场类型、与背景音乐节拍的对齐关系
4. 构图与景别：主体在画面中的位置、每个镜头的景别（远景/中景/近景/特写）
5. 光影与色调：光源方向、明暗对比、整体色温与调色风格
6. 背景环境：场景、道具、背景元素保持不变

# 必须替换
主体人物 → 用户提供的人物素材
替换时须保持以下不变：
- 人物在每个镜头中的画面位置与占比
- 人物的朝向、视线方向
- 人物的动作类型与幅度
- 人物与背景的遮挡关系和空间层次

# 严格禁止
1. 禁止增加或减少分镜数量
2. 禁止改变分镜顺序
3. 禁止添加参考视频中不存在的转场、特效、贴纸、滤镜
4. 禁止在画面中生成任何文字、字幕、水印、logo
5. 禁止改变画幅比例
6. 禁止改变整体色调风格
7. 禁止生成参考视频中不存在的场景或道具

# 输出规格
- 画幅比例：9:16（竖屏）
- 时长：与参考视频完全一致
- 帧率：与参考视频一致
```

【关键设计说明】

- **保持项拆成 6 个可独立判定的维度**：笼统写"结构一致"模型无法执行，拆开后每项都能单独对齐
- **替换项显式声明了 4 项"跟着不变"**：只说"换人"时模型常连带改变人物位置和动作幅度，导致结构偏离
- **禁止生成文字单独列为一条**：生成模型常自行添加字幕，若下游还要叠加自己的字幕会出现双字幕
- **画幅写死不依赖推断**：让模型从参考视频推断画幅存在不确定性，直接指定更可靠

【推断的信息】

- 画幅比例：按短视频场景默认 9:16，若参考视频为横屏请改为 16:9
- 未提供"是否需要替换场景/商品"，本 Prompt 按"仅替换人物"处理

【调优建议】

- 若生成结果结构偏离参考视频 → 检查"必须严格保持"是否覆盖了偏离的那个维度，缺失则补充
- 若人物替换后动作变形 → 强化"必须替换"下的保持项，可补充具体的动作描述
- 若画面仍出现文字 → 参考视频若自带字幕，需在生成前使用字幕擦除处理，仅靠 Prompt 无法可靠消除
- 若竖屏效果显著差于横屏 → 属模型在该画幅上的能力分布问题，Prompt 无法解决

## 自检清单

生成后逐条检查，不通过直接改。

**通用**
- [ ] Role 是职业身份 + 场景限定词，不是"专业助手"
- [ ] Task 写的是产出物，不是动作
- [ ] 一个 Prompt 只有一个产出物
- [ ] 所有主观判断都给了明确依据
- [ ] 所有模糊词（具体/生动/粒度细）都翻译成了结构约束
- [ ] Rules 里有具体的反面清单，不只有正面要求
- [ ] 多来源 Context 的语义空间不重叠

**A 类补充**
- [ ] 保持项拆到了可独立判定的维度（不少于 4 项）
- [ ] 替换项写清了"什么跟着变、什么不变"
- [ ] 禁止项包含"禁止生成任何文字"
- [ ] 输出规格写死了画幅，不依赖推断

**B 类补充**
- [ ] 有结构定义 + 完整示例
- [ ] 字段约束就近写在字段旁
- [ ] **定义了无结果时的返回**
- [ ] 枚举字段列出了完整枚举
- [ ] 嵌套不超过 3 层
- [ ] 有格式禁令三条
- [ ] Context 每个字段写了失效条件

**C 类补充**
- [ ] 有让模型表达"处理不了"的字段
- [ ] 写清了不知道时说什么（具体话术）

## 诊断：Prompt 改不动的时候

**改 Prompt 之前先判断这是不是 Prompt 能解决的问题。**

| 现象 | 是 Prompt 问题吗 | 该做什么 |
|---|---|---|
| 同一输入跑 5 次，有成功有失败 | ✅ 是 | 加约束，收窄输出空间 |
| 同一输入跑 5 次，5 次全失败 | ❌ 能力缺失 | 换模型，或在产品层规避 |
| 某一类输入（如竖屏）全部失败 | ❌ 输入分布问题 | 前置处理，或换模型 |
| 输出格式偶发错乱 | ⚠️ 部分是 | Prompt 侧 + 解析侧都做 |
| 输出混着思考过程 | ❌ 参数配置问题 | 检查思考模式是否显式关闭 |

**「同一输入跑 5 次」是成本最低的诊断动作**，能区分"能力缺失"和"能力不稳定"这两类需要完全不同处理的问题。

## 调优方法

**一次只改一处**，并记录：

| 版本 | 改了什么（只一处） | 测试集通过率 | 结论 |
|---|---|---|---|
| v1 | 基线 | 62% | — |
| v2 | 加禁用词清单 | 78% | ✅ 留 |
| v3 | 加 Few-shot 错误示例 | 85% | ✅ 留 |
| v4 | Role 改为资深运营 | 84% | 无影响，可回退 |

一次改多处时，效果变化无法归因，下次遇到同类问题无法复用结论。这张表本身也是 Prompt 的版本管理。
