# 多模态节点是成本大头

> 一条在多个项目里被反复验证的规律，以及它对产品设计的直接影响。

---

## 结论先行

在包含视觉理解的 AI 产品链路中：

> **视觉理解节点通常占据总成本的 90% 以上，所有文本节点加起来不到 10%。**

这条规律的直接推论是：

| 推论 | 说明 |
|---|---|
| **优化文本节点的 Prompt 长度是无效努力** | 省掉 30% 的文案 Token，对总成本的影响不到 2% |
| **降本只有两条路** | 降低视觉节点的**调用频次**，或等待更便宜的视觉模型 |
| **「降低调用频次」会改变产品形态** | 这是产品决策，不是技术优化 |

---

## 一个真实的成本结构

以下是一个「多素材智能剪辑」链路的成本拆解。链路包含 6 个节点，输入约 8 个视频素材，输出约 30 秒成片。

> 数值已按公开模型定价重新构造为等价示例，仅保留结构与比例关系。

| 节点 | 使用模型 | 成本占比 |
|---|---|---|
| **高光识别** | 视觉大模型（72B）+ 小模型（7B）判边界 | **≈ 63%** |
| **剪辑思路分析** | 视觉大模型（72B），输入 8 张关键帧 | **≈ 31%** |
| 片段排序 | 通用文本模型 | ≈ 2.8% |
| 文案生成 | 通用文本模型 | ≈ 1.6% |
| 封面生成 | 通用文本模型 | ≈ 1.2% |
| 智能包装 | 通用文本模型 | ≈ 1.0% |

**两个视觉节点合计 ≈ 94%，四个文本节点合计 ≈ 6.6%。**

### 为什么差距这么大

三个因素叠加：

**1. 单价差异（约 10 倍）**

以公开定价对比（每百万 Token）：

| 模型类型 | 输入 | 输出 |
|---|---|---|
| 视觉理解大模型 | ¥6.42 | ¥19.26 |
| 通用文本模型 | ¥0.69 | ¥1.38 |

**2. Token 消耗量差异（数十倍）**

- 一张图片（帧）消耗约 **700~800 Token**
- 一段文案生成任务的完整输入输出加起来约 **1600 Token**

而视频分析要按帧采样。以 `fps=1` 分析 60 秒视频 = 60 帧 = **约 45,000 Token**，是一次文案生成的 **28 倍**。

**3. 调用次数差异**

文本节点通常单次调用即可，而视觉节点可能需要多次：
- 逐片段分析（每个素材一次）
- 边界判断（示例中平均每 5 秒判断一次，60 秒视频判断 11 次）

三者相乘，就是 90:10 的成本结构。

## 这条规律怎么用

### 用法一：方案设计阶段就做成本预估，而不是上线前

传统产品的成本是固定的（服务器、带宽），可以最后再算。AI 产品的成本是**按调用量线性增长**的，而调用量由**产品设计**决定。

所以在方案设计阶段就应该回答这三个问题：

```
Q1. 这条链路里有几个视觉理解节点？
Q2. 每个视觉节点的调用次数由什么决定？（素材数量？时长？用户操作？）
Q3. 最坏情况下（用户传了最多素材、最长视频），单次成本是多少？
```

**第三个问题最容易被忽略，也最容易出事。** 因为平均成本可控不代表长尾可控——如果用户传了 20 个 5 分钟的素材，成本可能是平均值的 30 倍。

### 用法二：识别「无效优化」

看到这张表之后，下面这些常见的优化动作可以直接判定为无效：

| 动作 | 为什么无效 |
|---|---|
| 精简文案生成节点的 Prompt | 该节点仅占 1.6%，砍一半 = 省 0.8% |
| 把文本节点换成更便宜的模型 | 4 个文本节点全免费也只省 6.6% |
| 优化输出格式减少 Token | 同上 |

而下面这些才是有效的：

| 动作 | 影响 |
|---|---|
| **降低视频分析的采样率**（fps 2→1） | 直接砍掉一半视觉 Token |
| **按素材时长分档处理**（只分析部分片段） | 长尾成本直接封顶 |
| **用小模型做预筛，大模型只处理候选** | 大模型调用次数下降 |
| **等待/推动视觉模型的降本方案** | 影响面最大但不由你控制 |

> 一个参考量级：在上述案例中，视觉模型侧的专项降本方案预期可将 60 秒视频的分析成本**降低约 85%**。这个幅度是任何产品侧的 Prompt 优化都不可能达到的。

### 用法三：把成本约束翻译成产品规则

这是最关键的一步。**成本优化最终一定会落到产品形态上**，因为「降低调用频次」本质是「少做一点事」。

以「按素材时长分档」为例，它最终变成了这样一条产品规则：

| 输入素材时长 | 输出成片时长策略 |
|---|---|
| ≥ 120 秒 | 取原时长的 1/4 |
| 30 ~ 120 秒 | 固定输出 30 秒 |
| < 30 秒 | 保留原时长 |

这条规则同时解决了两件事：
- **成本**：长视频不再全量分析，长尾成本被封顶
- **观感**：素材长不代表用户想要长成片，30 秒左右是短视频的舒适区间

**代价**：

| 代价 | 说明 |
|---|---|
| 用户失去时长控制权 | 传了 10 分钟素材，只能拿到 2.5 分钟成片，且无法自选 |
| 分档边界处体验跳变 | 传 29 秒和 31 秒素材，输出策略完全不同，用户会困惑 |
| 规则需要向用户解释 | 但解释成本高，多数产品选择不解释，于是变成隐性预期落差 |

## 成本拆解的操作方法

### 第一步：按节点建成本台账，不要按调用次数

常见错误是用「单次调用成本 × 调用量」估算。这个算法在多节点链路里完全失效，因为**每个节点的单价、Token 量、调用次数都不同**。

正确的台账结构：

| 节点 | 模型 | 输入 Token | 输出 Token | 输入单价 | 输出单价 | 调用次数 | 小计 |
|---|---|---|---|---|---|---|---|
| 节点 A | | | | | | | |
| 节点 B | | | | | | | |

模板见 [templates/cost-ledger.md](../templates/cost-ledger.md)。

### 第二步：定义清楚「一次业务操作」

成本必须挂在**用户能感知的业务动作**上，而不是技术调用上。

- ❌ 「单次模型调用成本 0.03 元」→ 无法用于定价
- ✅ 「用户生成一条成片的成本 0.27 元」→ 可以直接推导定价

这中间的换算关系（一次成片 = 多少次模型调用）必须显式写清楚，因为它会随素材数量变化。

### 第三步：明确「按什么变量线性增长」

链路中不同节点的增长因子不同：

| 节点 | 成本随什么增长 |
|---|---|
| 高光识别 | 素材**总时长**（按帧采样） |
| 剪辑思路 | 素材**数量**（每个素材抽关键帧） |
| 文案 / 排序 / 包装 | 基本恒定 |

**搞清增长因子，才知道该限制什么。** 上例中限制时长（而不是限制素材数量）是更有效的降本手段，因为高光识别是最大成本项。

### 第四步：用最坏情况定兜底规则

按 P99 输入（而不是平均输入）算一遍成本。如果最坏情况的成本超出可接受范围，必须在产品层加硬限制：

- 单次上传素材数量上限
- 单素材时长上限
- 单用户每日调用次数上限

这些限制会损伤体验，但**没有上限的 AI 产品在成本上是不可控的**。

## 关于定价倍数

从成本推导定价时，常见做法是乘一个系数（例如 **1.3 倍**）。这个系数覆盖的不是利润，而是被成本台账漏掉的部分：

| 漏掉的部分 | 说明 |
|---|---|
| **失败重试** | 失败的调用同样产生成本，但不产生价值 |
| **用户重新生成** | 对结果不满意时的重试，是 AI 产品的高频行为 |
| **存储与 CDN** | 生成物的存储和分发 |
| **辅助 API** | 例如字幕擦除、转码、ASR 等前置处理 |
| **模型侧价格波动** | 定价周期通常长于模型降价周期，需要留缓冲 |

所以这个系数不该拍脑袋定，应该反过来估：

```
系数 ≈ 1 + 失败率 + 平均重试次数 × 单次成本占比 + 辅助服务占比 + 安全垫
```

**如果你的失败率是 8%、平均重试 0.5 次，那 1.3 倍其实是偏紧的。**

---

## 一条容易被忽略的成本项：失败也要付钱

模型调用一旦发出，即使结果不可用（格式错误、内容为空、被安全策略拦截），Token 也已经消耗。

这意味着：

> **鲁棒性问题不只是体验问题，它直接体现在成本上。**

一个 20% 解析失败率的链路，等于凭空多付 20% 的成本，而且这部分成本**完全不产生用户价值**。

这是 [03 章鲁棒性](../03-robustness/) 与本章的连接点——**提升成功率本身就是最直接的降本手段**，而且它不需要牺牲任何产品体验。
