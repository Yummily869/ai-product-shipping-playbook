# 竖屏导致的双字幕问题

> 这是我实习期间排查时间最长、也最有收获的一个问题。

---

## 现象

爆款复刻功能提测时，**badcase 率 70%**。

具体问题是：用户上传的原视频自带字幕，我们生成的新视频**没有把原字幕消除掉**，同时又叠加了我们自己生成的字幕——结果画面上出现两层字幕。

---

## 排查过程

### 第一步：找上游团队

字幕消除是视频生成模型（Seedance 2.0）的能力，所以我们找了对方团队协助。

对方给了提示词撰写的方法，我们照着改了，**没有效果**。

### 第二步：对方说复现不了

这是最卡的地方。

> **对方用 50 个视频测试，0 例出现双字幕。**

而我们这边 70% 都有问题。同一个模型、同一套提示词、结论完全相反。

当时我很困惑，因为这看起来像是「我们哪里用错了」，但检查了好几遍配置都没问题。

### 第三步：长时间沟通后发现根因

来回沟通了很久，最后才定位到：

> **根因是横屏 vs 竖屏。**
>
> - 横屏视频：字幕消除效果良好
> - 竖屏视频：双字幕概率极高

对方测试用的素材是横屏的，我们线上的用户素材绝大多数是竖屏的。

**双方都没意识到自己有「默认画幅」这个前提。**

### 最终解法

接入了专门的**字幕擦除 API**，在视频生成之前先把原字幕擦掉，不再依赖生成模型自己处理。

---

## 我从这件事学到的

### 1. 「对方复现不了」是信号，不是噪音

我一开始的反应是「那应该是我们用错了」，然后花时间去检查自己的配置。

现在我的理解是：**当上游说「我们测了没问题」时，第一件事不该是怀疑自己，而是比对双方的输入特征。**

因为「我这边好的」和「你这边坏的」同时成立，唯一的解释就是**输入不一样**。

### 2. 我做了一张输入特征比对清单

这是我从这件事里得到的最实用的东西。以后遇到类似情况，我会直接拉着对方逐项对：

| 维度 | 我方 | 对方 | 一致？ |
|---|---|---|---|
| 画幅比例（横/竖/方） | | | |
| 分辨率 | | | |
| 时长分布 | | | |
| 是否含原生字幕 | | | |
| 码率 | | | |
| 有无人声 | | | |
| 内容垂类 | | | |
| 素材来源（拍摄/下载/截屏） | | | |

**第一行如果我们一开始就对了，能省下大量时间。**

### 3. 默认前提必须显式写出来

对方的测试素材是横屏，这件事对他们来说是「不需要说明的常识」；我们的用户是竖屏，这对我们也是「不需要说明的常识」。

**两边都觉得不用说，所以都没说。**

我现在写需求或提 bug 时会尽量把这类前提写出来，即使觉得对方应该知道。

### 4. 这个问题应该在选型阶段就被发现

事后想，如果选型测试集里竖屏占比和线上一致（90%），这个问题在选型阶段就会暴露，不会拖到提测。

所以我现在做选型会先填测试集分布对照表。见 [模型选型 skill](../skills/model-selection/README.md)。

---

## 解法的代价

接字幕擦除 API 不是没有成本的：

| 代价 | 说明 |
|---|---|
| 增加成本 | 多了一个 API 调用 |
| 增加链路长度 | 多一个环节 = 多一个失败点 |
| 增加耗时 | 擦除本身需要时间 |
| 只是降低而非消除 | 擦除本身也有失败率 |

我觉得记录代价挺重要的，因为这决定了「这个解法能撑多久」——如果后续成本压力变大，这个环节可能就是第一个被质疑的。
