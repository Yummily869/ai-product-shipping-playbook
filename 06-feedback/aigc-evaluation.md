# AIGC 效果评测体系

> 主观效果如何变成可判定、可对比、可推动迭代的分数。

---

## 核心难题

AIGC 产品的效果评测有一个绕不开的矛盾：

> **用户最终感受到的是「这条视频好不好看」，但「好不好看」既不可量化，也无法定位到具体环节。**

两种常见的失败做法：

| 做法 | 问题 |
|---|---|
| **只打总分**（这条片子 7 分） | 知道好不好，但不知道该改哪个节点 |
| **只看节点技术指标**（识别准确率 92%） | 每个节点都达标，合起来还是不好看 |

**解法是：按链路环节拆分权重，每个环节再拆成可判定的子项。**

---

## 一个可直接复用的三维框架

以「多素材智能剪辑」为例，最终成片质量拆成三个维度：

```
                    评测指标
                       │
      ┌────────────────┼────────────────┐
      │                │                │
  高光识别质量      文案生成匹配度     智能包装观感
     30%              40%               30%
      │                │                │
  ├─内容准确性     ├─内容相关性     ├─字幕排版合理性
  └─画面质量       ├─风格适配性     ├─视觉风格统一性
                   └─叙事连贯性     └─文字模板适配性
```

### 三个维度对应链路的三个阶段

| 维度 | 对应链路阶段 | 回答的问题 |
|---|---|---|
| **高光识别质量** 30% | 输入理解 | 选对片段了吗 |
| **文案生成匹配度** 40% | 内容生成 | 讲对故事了吗 |
| **智能包装观感** 30% | 视觉呈现 | 呈现得好看吗 |

> **这个拆法的价值：总分低时，能直接定位到是哪个阶段的问题。** 而这正是「只打总分」做不到的。

### 为什么文案是 40%（权重怎么定）

权重不该拍脑袋。判断依据是**该环节对最终感知的影响力 × 该环节的失败概率**。

文案给 40% 的理由：

| 理由 | 说明 |
|---|---|
| **感知最直接** | 用户看视频时字幕是唯一的显性文字信息，一句尬文案会毁掉整条片子 |
| **失败模式最多** | 内容不相关、风格不搭、前后不连贯，三种失败方式 |
| **最能体现差异化** | 这是模板方案做不到的部分，也是本产品的核心价值所在 |

而高光识别和包装各 30% 的理由：
- 高光识别虽然是**错误代价最高**的环节（选错了后面全错），但它的失败**会通过文案和观感体现出来**，不需要重复计权
- 包装的问题**用户可以手动改**（换个字体、调个位置），影响面小于前两者

> **权重设计的一个原则：不要给"错误会传导到下游"的环节过高权重**，否则同一个问题会被计分两次。

---

## 各子项的判定标准

评测框架的价值全在这一层。**没有明确判定标准的子项，等于没有这个子项**——因为不同评估人会给出完全不同的分数。

### 高光识别质量（30%）

| 子项 | 判定标准 | 打分方式 |
|---|---|---|
| **内容准确性** | 选出的片段是否包含明确的人物动作/事件，而非静态空镜或废片 | 逐片段判定「是否为有效高光」，算比例 |
| **画面质量** | 是否清晰、无明显抖动、无虚焦、主体未被裁切 | 逐片段四项检查，全通过算合格 |

**内容准确性的评分细则（避免主观分歧）**：

```
2 分（好）：包含明确的人物动作或事件，构图完整
1 分（可用）：有内容但表现力弱（如平缓的风景移镜）
0 分（差）：静态空镜、纯过渡帧、废片（黑屏/糊/手指遮挡）
```

**这套细则的关键是把 0 分定义清楚**。因为评估人对"好"的理解差异大，但对"这是废片"的判断高度一致——**从坏的一端锚定标准，一致性显著高于从好的一端**。

### 文案生成匹配度（40%）

| 子项 | 判定标准 | 常见失败 |
|---|---|---|
| **内容相关性** | 文案描述的是否是画面里实际存在的东西 | 画面是猫，文案写"和朋友的午后"（幻觉） |
| **风格适配性** | 是否符合用户选定的风格 | 用户选"诗意"，输出吐槽风（见下） |
| **叙事连贯性** | 多条字幕连起来是否构成一个完整表达 | 每句单看都行，连起来是六句无关的话 |

**「叙事连贯性」是最容易漏掉的子项**，也是最能体现产品价值的子项。

判定方法：**把所有字幕单独抽出来连读**。如果连读起来像一段话，就通过；如果像六条独立的朋友圈，就不通过。

> 这个子项之所以重要：它是「大模型编排」相对于「模板填充」的核心优势所在。**如果连贯性不达标，产品就失去了存在的理由**——模板方案也能做到"每句话单看都对"。

**风格适配性的一个真实 badcase**：

用户明确选择「诗意表达」，输出却是吐槽风。根因不在文案节点本身，而在上游内容标签携带了风格语义，与用户选择的风格冲突。

> **这说明一件事：评测分数低的环节，根因可能在上游。** 所以评测体系必须配合链路追踪使用，见 [Agent 评测体系 · 三层评测](./agent-evaluation.md)。

### 智能包装观感（30%）

| 子项 | 判定标准 | 常见失败 |
|---|---|---|
| **字幕排版合理性** | 是否遮挡主体、是否出屏、换行是否在语义断点 | 字幕压在人脸上；长句被裁断 |
| **视觉风格统一性** | 全片的字体/配色/转场是否属于同一套风格 | 前三段是清新风，后两段变成科技风 |
| **文字模板适配性** | 选用的文字模板是否匹配内容调性 | 温情内容配了夸张的综艺花字 |

**这三项都是「可以用规则部分覆盖」的**：

| 子项 | 可否规则化 |
|---|---|
| 字幕排版 | ✅ 大部分可以（人脸检测避让、安全区约束、按标点换行） |
| 风格统一性 | ✅ 完全可以（全片共用一套风格配置，不逐段选择） |
| 模板适配性 | ❌ 需要模型判断内容调性 |

> **评测发现问题后，第一反应不该是"改 Prompt"，而是"这个问题能不能用规则解决"。** 上面前两项用规则解决的稳定性远高于依赖模型。

## 评测的执行方法

### 1. 双人交叉 + 一致性检查

主观评分必须至少两人独立打分。

**关键动作：先算一致率，再看分数。**

```
一致率 = 两人打分完全相同的样本数 / 总样本数
```

| 一致率 | 含义 | 动作 |
|---|---|---|
| > 80% | 标准清晰 | 分数可信，继续 |
| 60-80% | 标准有歧义 | 找出分歧样本，细化判定标准 |
| < 60% | 标准失效 | **停止评测，重写细则** |

> **一致率低时，分数是无意义的。** 很多团队跳过这一步直接用平均分，结果分数波动完全来自评估人差异而非产品变化。

### 2. 基准测试集：只增不改

| 规则 | 原因 |
|---|---|
| **分布与线上一致** | 否则选出的是"在测试集上好"的方案 |
| **只增不删** | 删掉的样本往往是"我们解决不了的"，删了就永远发现不了 |
| **每个线上 badcase 都补进去** | 这是测试集唯一正确的增长方式 |
| **规模不必大** | 30-50 个高质量样本足够看趋势 |

**必须包含的极端样本**：
- 纯黑/纯白画面
- 无人声素材
- 超短素材（< 3 秒）
- 超长素材（> 5 分钟）
- 单素材 / 超多素材（20+）
- 各画幅比例（横屏/竖屏/方形）

### 3. LLM-as-a-Judge：能用，但要先对齐

用大模型做评分可以大幅降低评测成本，但**必须先验证它和人的判断一致**。

**正确流程**：

```
① 人工评 50 个样本 → 作为标准答案
② 让模型评同一批 → 算模型与人的一致率
③ 一致率 > 80% → 可以用模型做大批量评测
④ 一致率 < 80% → 改评分 Prompt，回到 ②
⑤ 上线后定期抽样人工复核，防止漂移
```

**哪些子项适合用模型评**：

| 子项 | 适合模型评 | 原因 |
|---|---|---|
| 内容相关性 | ✅ | 有客观依据（画面 vs 文案） |
| 叙事连贯性 | ✅ | 纯文本判断，模型擅长 |
| 风格适配性 | ⚠️ 需谨慎 | 风格是主观概念，需要充分的 Few-shot |
| 画面质量 | ❌ | 用传统 CV 指标（清晰度/抖动）更准更便宜 |
| 字幕排版 | ❌ | 用规则检测（人脸框重叠/出屏）即可 |

> **注意最后两行**：不是所有子项都该用大模型评。**能用确定性方法测的，用确定性方法**——更准、更快、更便宜。

### 4. 评测必须产出「问题分布」而不只是分数

一份只有分数的评测报告价值有限。**有价值的输出是失败模式的分布**：

```
本轮评测 50 个样本，综合得分 6.8 / 10

失败模式分布：
  文案与画面不相关          32%  ← 主要矛盾
  字幕遮挡主体              24%
  叙事不连贯                18%
  选中了废片                14%
  风格不符合用户选择        12%
```

**这张分布表直接就是迭代优先级。** 而单一的 6.8 分无法告出你该先做什么。

## 从评测到迭代的闭环

评测体系的目的不是打分，是驱动迭代。完整闭环：

```
① 定义维度与权重
      ↓
② 写清每个子项的判定标准（含 0 分定义）
      ↓
③ 建基准测试集（分布对齐 + 只增不改）
      ↓
④ 双人交叉打分 → 先看一致率，再看分数
      ↓
⑤ 输出失败模式分布 → 得到迭代优先级
      ↓
⑥ 针对 Top1 失败模式做单变量改动
      ↓
⑦ 在同一测试集上复测 → 对比
      ↓
⑧ 线上 badcase 补入测试集 → 回到 ③
```

**第 ⑥ 步的「单变量」是关键**。一次改三处，效果变好也不知道是哪处起作用，下次遇到类似问题无法复用。

## 常见误区

| 误区 | 为什么错 |
|---|---|
| 只打总分不拆维度 | 无法定位问题环节 |
| 权重按「重要性」直觉分配 | 应按「影响力 × 失败概率」，且避免上游问题重复计分 |
| 子项没有 0 分定义 | 评估人一致率会很低，分数不可信 |
| 跳过一致率直接用平均分 | 分数波动来自人而非产品 |
| 测试集删掉难样本 | 永久失去发现该类问题的能力 |
| 所有子项都用大模型评 | 能用规则测的用规则，更准更便宜 |
| 只输出分数不输出失败分布 | 拿不到迭代优先级 |
| 发现问题就改 Prompt | 应先判断能否用规则解决、根因是否在上游 |
