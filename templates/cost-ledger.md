> 用法：方案设计阶段填写，不要等到上线前。

---

## 第一步：定义「一次业务操作」

成本必须挂在**用户能感知的业务动作**上，而不是技术调用上。

```
一次业务操作 = ______________________（例：用户生成一条成片）

它包含的模型调用次数 = ______________
这个次数由什么变量决定 = ______________（素材数？时长？固定？）
```

## 第五步：定价系数推导

不要直接拍 1.3 倍。按下面逐项估：

```
系数 = 1
     + 失败率                      ______  （失败也消耗 Token）
     + 平均重试次数 × 单次成本占比    ______  （用户对结果不满意的重试）
     + 辅助服务成本占比              ______  （转码/擦除/ASR/存储/CDN）
     + 模型价格波动安全垫            ______
     ─────────────────────────────
     = 最终系数                     ______
```

## 第六步：降本机会盘点

先看占比最高的节点，其余节点不要浪费时间。

| 节点（按占比降序） | 占比 | 可行降本手段 | 预期降幅 | 产品代价 |
|---|---|---|---|---|
| | | | | |
| | | | | |

**常见降本手段**：

| 手段 | 适用条件 | 典型代价 |
|---|---|---|
| 降低采样率（fps） | 视觉理解节点 | 可能漏掉关键帧 |
| 按输入分档处理 | 长尾输入占比高 | 用户失去控制权、边界体验跳变 |
| 小模型预筛 + 大模型精处理 | 候选集可被快速过滤 | 预筛可能误杀 |
| 子任务降档 | 任务可拆成判断类 + 理解类 | 拆分本身增加链路复杂度 |
| 缓存复用 | 同一输入会被重复处理 | 缓存一致性问题 |
| 提升成功率 | 失败率 > 5% | **无代价，优先做** |

> **最后一行值得特别注意**：失败的调用同样消耗 Token 但不产生价值。修好解析层往往比任何优化都更有效，且不牺牲任何体验。
